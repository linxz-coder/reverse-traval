# 城市酒店榜单数据要求

## 目标榜单

后续先支持两类榜单：

- 亲子酒店不涨价榜：每个城市按儿童设施、泳池、房型可订、含税价稳定度和评分排序。
- 星级酒店不涨价榜：每个城市按高星酒店、评分、含税价稳定度和可订房型排序。

每个榜单都按城市、假期、入住日期、离店日期生成一个快照。快照保留历史记录，前端和后台默认读取最新成功快照。

## 必填数据

### 榜单快照

- 城市中文名、Trip.com cityId、国家/省份。
- 榜单类型：`family_no_surge` 或 `star_no_surge`。
- 假期编码、假期中文名、入住/离店日期、晚数。
- 搜索模式：单城市或周边城市。
- 筛选条件：高级酒店、儿童设施、泳池、房型、价格区间。
- 价格规则：是否含税、对比日期数量、最大涨价金额、最大涨价比例。
- 运行状态：待开始、运行中、成功、失败。
- 统计结果：抓到酒店数、符合条件酒店数、推荐酒店数、生成时间、过期时间。

### 酒店条目

- 排名、酒店 ID、简体中文酒店名、原始酒店名。
- 城市、区域、星级、评分。
- 房型中文名、原始房型名。
- 假期含税均价、对比日期均价、涨价金额、涨价比例。
- 不涨价判断：未涨、轻微涨价、涨价、未知。
- 推荐理由、标签、设施、可订情况。
- 原始抓取数据 JSON，方便后续修正规则。

### 酒店价格观测

- 酒店 ID、Trip.com 酒店 ID、简体中文酒店名、原始酒店名。
- 城市中文名、区域中文名。
- 价格日期、入住日期、离店日期、晚数。
- 房型中文名、原始房型名。
- 币种、基础价、税费、含税价、每晚含税均价。
- 早餐、取消政策、是否可订。
- 数据来源：DOM、接口、缓存、手工导入。
- 搜索任务 key、关联榜单快照 ID、抓取时间。
- 原始价格 JSON，方便后续排查和重算。

## 数据库表

- `ranking_profiles`：榜单类型和默认规则。
- `ranking_cities`：可预热缓存的城市基础信息。
- `hotel_profiles`：酒店基础信息，按酒店 ID 去重。
- `hotel_price_observations`：每次抓到的酒店日期价格，保留历史。
- `ranking_snapshots`：每次城市榜单生成快照。
- `ranking_hotels`：每个快照里的酒店排名和价格对比。
- `v_latest_hotel_prices`：每个酒店、日期、房型的最新价格视图。
- `v_latest_ranking_hotels`：最新成功榜单视图，方便 Navicat 直接查看。

## 搜索缓存复用

搜索过程中会把已展示的酒店结果写入 `hotel_price_observations`：

- `price_role = holiday`：假期入住时段的含税总价和每晚均价。
- `price_role = comparison`：代表平日样本的含税价和每晚均价。
- `holiday_code`：把假期价和对应的平日对比价归到同一个榜单/搜索场景。
- `is_advanced`、`has_pool`、`has_child_facility`：用于 MySQL 价格预览时尊重前端筛选条件。

当文件缓存没有命中时，前端可先显示 MySQL 价格缓存预览；后台仍会继续完整搜索、对比和设施核验，最终结果以完整搜索为准。
